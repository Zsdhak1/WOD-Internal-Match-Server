# 服务端本地全场摄像头

## 使用

1. 将 USB 摄像头接入运行服务端的 Windows 电脑；关闭可能独占设备的 Windows 相机、会议软件等。
2. 在服务端「本地全场摄像头（USB / 内置）」选择设备，可用「刷新设备」更新列表。
3. 点击「启动采集」。收到首帧之前显示“等待首帧”，不能把启动成功等同于收到图像。
4. 点击「切到全场」，或点击下方全场缩略图；全场源 ID 为 `field`，支持现有手动/自动导播切换；自动导播跳过尚未采集或无信号的本地全场源，避免轮到占位机位时黑屏。
5. 「停止采集」立即释放设备并清除旧帧；程序启动只记忆设备 ID，不自动开启摄像头。

本地机位不登记选手、不占用红蓝 TCP 会话和 UDP 视频端口，不需要 FFmpeg 采集/编码/解码。画面由 Qt Multimedia（QMediaDevices / QCamera / QVideoSink）直接传给服务端 BroadcastWindow，主画面沿用现有 VideoCanvas。不会将全场视频自动发送给选手端，也不录音/录像。

## 适配及恢复

- 以设备 ID 区分同名摄像头，记忆上次选择；刷新不偷偷改选其它设备。
- 按原始分辨率采集：在能达到 30 FPS 的设备公开格式里选分辨率最高的（上限 3840×2160），同分辨率下优先 ARGB、帧率最接近 30；没有能到 30 FPS 的格式时选帧率最高的。转播屏按原始分辨率显示，缩略图和节目监看最大 720p。Qt backend 决定实际 FPS。
- 断开时清除全场缓存/缩略图，显示等待重连；只自动重连同一设备。停止后不再重连。
- 相机错误/6 秒无帧会释放设备并重试，延迟 1/2/4 秒，三次恢复失败后停止并提示权限、占用、USB 检查；持续有效采集 10 秒后重置失败预算。
- 换设备会关闭旧设备、清除旧帧再打开新设备；代次标记拒绝已关闭设备的晚到帧。
- 采集独立于比赛：暂停、结束和比赛重置不关摄像头；退出服务端释放设备。

## 验证边界

FieldCameraTest 使用可注入 fake backend，覆盖默认不采集、设备 ID、首帧、非720p输入、断开/重连、失败预算和停止。SimulatorIntegrationTest 检查实际服务端 UI 控制、全场 frame 路由、缩略图、导播、比赛独立性及失去信号清帧。自动测试不打开用户摄像头。

硬件 UVC/厂商驱动、USB 带宽、Windows 摄像头隐私权限、GPU 和长时间稳定性需用真实摄像头联调，不能由上述 fake 测试证明。若列表为空，请检查 Windows 设置 → 隐私和安全性 → 摄像头 → 允许桌面应用访问；若有设备无帧，检查独占和驱动。
