# 规则符合性审查：中俄大学生机甲挑战赛

审查日期：2026-10-10。范围：当前工作区的 Qt 服务端、选手端、机器人模拟器、检录模式和独立结果网页；未更改比赛源码，未证明实车固件/物理装置符合。

## 一、结论

**当前不能作为该手册规则下的正式自动裁判和正式成绩统计系统。** 现有系统仍是此前约定的“60秒、击杀+1、同分突然死亡”模式；手册要求“180秒、BO3、有限复活、剩余复活次数/血量判胜、小组胜场与获胜点排名”。这是规则模型的差异，不是换标题或表格列名能解决。

现有视频、HUD、设备通信、健康检录和网页布局可复用。300HP/每击20的模拟路径和热量显示参数有对应实现，但不能由模拟器或HUD推断真机符合。正式切换前需要新增明确规则配置、改造结果数据模型并完成实车验收。

## 二、依据及审查方法

- 原始输入：用户提供的《第二届中俄大学生科技人文交流活动方案（科创创意团队机甲挑战赛）规则手册》。手册原件不随源码仓库发布；依据正文第六章比赛规则、第七章赛制与赛程、第九章安全应急。
- 使用 python-docx 按正文/表格顺序读取93段正文、3张表格；无内嵌图片。完整提取与探针脚本保留在本机忽略的 build/verification，不把私人文档或本机路径加入提交。
- 源码审查前读取 CodeGraph 说明并调用 context，随后以实际源码为依据。
- 对网页 Store 使用独立临时 SQLite 做三个兼容性探针，不启动比赛服务、不操作真机、不改正式数据库。
- 既往7项桌面CTest、9项网页回归和4分辨率布局测试检验旧模型与稳定性，不能代替本手册符合性验收。本次没有重跑桌面构建或硬件测试。

## 四、网页兼容性实际探针

兼容性探针使用临时数据库，运行完成后清理；脚本保留在本机 build/verification，不作为正式业务测试或赛事规则实现。

1. `A/B击杀均0，但裁判按最终HP指定A赢`：返回400，要求同分必须加时。手册允许剩余复活相同而HP不同直接定胜，不应强迫SD。
2. `A获胜点+100，B获胜点-100`：返回400，当前score_b只接受非负整数。
3. 构造A总击杀38但只赢1场，B总击杀10但赢2场：当前排名A在B前。手册要求先比赢场，应B在前。

这些不是手册指定的完整BO3测试；它们证明当前字段/校验/排序无法直接承载正式成绩。

## 五、手册本身需要裁判组确认的边界

1. **3次复活的重置范围**：“每场比赛3次”与“每小局”并存。是每个3分钟小局重置，还是整个BO3共享3次？不能自行假定。
2. **到时剩余复活和HP均相同**：没有下一条判定；SD并非手册授权。须明确平局/重赛/延长时间/指定加时规则。
3. **双方均耗尽复活并同时归零**：无同时淘汰规则。
4. **获胜点平均与总和**：逐小局可按 `有效剩余HP = HP + 300×剩余复活次数` 计算差；但BO3平均分母、跨BO3小组总和采用原始小局点还是整场平均点、2:0与2:1权重、罚负/安全终止/重赛计分方式需统一。
5. **黄牌扣血**：文字明确首次50，第二次是否也50、低于50归零是否耗复活、第三张判负作用于小局或整场？当前代码每张都记50，不能默认为正式解释。
6. **安全故障成绩**：详细规则区分非人为可申请重赛/人为判负；应急章节说按当前有效分数记录。两者优先级须确认。
7. **仍同胜场同获胜点**：没有进一步小组排序规则；不能暗中使用净击杀或名称排晋级。
8. **时间预算**：每半天32场BO3、2场地，至少16个场次波次。所有场打满3局时每BO3=3×3+2×2=13分钟，理想同步16波=208分钟，再加15次整场间隔1分钟=223分钟，已超过9:00–12:30或14:30–18:00的210分钟。尚未含重赛/故障。该项是最坏情形规划风险，不是断言必然超时，应预留缓冲或由主办方调整排程。

## 六、整改优先级（本次只审查，不执行）

### P0：正式比赛前必须解决

- 新增具名比赛规则配置，保留旧击杀模式，避免静默覆盖既有需求。
- 正式180秒、有限复活状态/5秒计时、耗尽死亡提前结算、到时复活数/HP比较；未知/失联数据不能自动当作0HP。
- 双方硬件急停和软件安全停赛闭环；物理断电确认、失败警示、故障原因、重赛/判负流程。远程命令不得替代实体急停。
- 明确当前场次两台合法机器人绑定；开局/黄牌/断电只能影响本场；A/B场地与调试区不会互发命令。
- 移除未经手册确认的自动SD与默认10秒离线判负（仅正式配置中，不擅改旧模式）。

### P1：计分及赛程

- BO3整场状态机：首赢2局结束、2分钟局间准备、1分钟整场间隔；按确认规则重置复活/黄牌。
- 每小局保存HP、剩余复活、胜负理由、获胜点及裁判修订证据；BO3公示平均值。
- 上午/下午分开、A–H分组、32场固定对阵和晋级/季军赛；按胜场和获胜点分组排名。
- 结果网页改字段、允许正负获胜点、支持人工判罚/重赛，明确人工录入或经审定的数据同步。

### P2：检录与显示

- 增加人工实物检录清单及放行签字；包括弹药/初速/弹量/急停/结构防护/机型。
- HUD显示剩余复活、复活倒计时、BO3小局号/胜局数；网页显示小组胜场和获胜点，不用击杀数代替。
- 可选双语队名/提示与裁判术语；手册要求双语翻译驻场，并不等于明文强制所有软件俄语化。

## 七、正式验收建议

- 初始HP300，15次合法命中归零，每次-20；无重复事件导致多扣。
- 死亡后至少5秒禁止复活攻击；仅3次成功复活，第4次死亡不能恢复；按确认的局/场边界重置。
- 到时：复活次数多者胜；同次数比HP；均同/同时淘汰按正式补充规则处理。
- BO3 2:0自动结束、不产生第3局；1:1进入第3局；准备阶段不误加伤害或消耗机会。
- 热200锁射、每发+10、每秒-10，等待实车遥测；初始装弹≤300、官方12mm弹、测速≤15m/s；实体急停测试。
- 一方安全故障，两方底盘实际断电且停赛；断网/ACK失败也必须有安全处理与人工复核。
- A场操作不影响B场或调试区；ID重复、未检录/未绑定机器人禁止正式开赛。
- 2:0和2:1获胜点案例、同胜场排序、罚负/重赛和上午下午隔离；4:3/16:9展示与导出一致。

**结论边界：本报告确认源码中的明确不一致和缺失；没有宣称已检验真实机器人、已部署固件或赛事现场。**
